## Traps found
- download.opensuse.org mirror is slow/intermittent for large RPMs (rootapp=356MB, zen=200MB+, obsidian);
  preloading may 404/timeout transiently - the RPMs exist (verify via downloadcontent.opensuse.org 200).
  Use zypper --dry-run for dep checks; for real installs use a retry loop.
- zypper syntax: `--no-recommends` goes AFTER `install`; `--dry-run` also after `install`
- GitHub Actions GITHUB_TOKEN expires mid-run (~1h after job start). The checkout `http.extraheader` keeps
  the ORIGINAL token and overrides fresh URL credentials, so `git push` fails with "Invalid username or
  token" even when the shell GITHUB_TOKEN is still valid for the API. FIX: refresh
  `git config --local http.https://github.com/.extraheader "AUTHORIZATION: basic $(printf 'x-access-token:%s' "$GITHUB_TOKEN" | base64 -w0)"`.
- `zypper install <local .rpm>` inside container fails; use repo install (zypper install <name>).
- GUI/Electron apps (opencode-desktop etc.) cannot fully launch in headless container (no X/Wayland) - verify
  binary presence + init; `--no-sandbox` needed as root.
- OBS API (api.opensuse.org) is a more reliable download host than the mirrors during mirror flakiness:
  fetch rpms from `https://api.opensuse.org/build/home:ackerman/<repo>/<arch>/<pkg>/<file>.rpm`.
- When mirrors are degraded: serve the downloaded rpms via `python3 -m http.server` on the host and install
  with `zypper --no-gpg-checks --non-interactive install --no-recommends http://172.17.0.1:8080/<file>.rpm`
  (plain-rpm URL repo; must use --no-gpg-checks for the unsigned plain-rpm repo).
- The `download.opensuse.org` redirect front and `downloadcontent.opensuse.org` both become flaky for large
  rpms (HTTP/2 stream reset CANCEL on ~250MB nodejs-electron); the mirror heals over time - retry.
- `zypper se <pkg>` can report "No matching items" when repo metadata load silently failed - re-add/re-refresh
  the repo rather than trusting the result.
